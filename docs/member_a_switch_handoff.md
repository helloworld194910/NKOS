## 2. 提交上层确认的接口

```c
long member_a_enter_user(uintptr_t entry, uintptr_t user_sp,
                         uintptr_t kernel_trap_stack_top);
long member_a_user_trap(struct trapframe *tf);
```

调用方在 S 态准备独立的用户代码页、用户栈和专用内核 Trap 栈，并安装页表；entry 和 user_sp 是用户虚拟地址，kernel_trap_stack_top 是内核虚拟地址且按 16 字节对齐。底层不分配页，不改 satp。内核映射始终不带 U 位。

上层回调返回 0：使用经合法处理的帧继续用户执行；返回 1：结束实验回到原内核函数调用点。底层正常返回 0，非法回调动作返回 -1；活动期间再次进入返回 -2。上层负责确认原因、ecall 语义和 epc；不把原 kernel ra 当作用户返回地址，也不把用户 ra 用作内核 ret。

本轮夹具中 0x5901 表示继续，0x5902 表示结束；这些编号只是候选测试协议，待上层同意或替换，并非正式系统调用编号。

## 3. 栈与 sscratch 的阶段约定

| 阶段 | 当前 sp | sscratch |
| --- | --- | --- |
| 调用前 | 原内核调用栈 | 原值，底层会保存 |
| 用户执行 | 用户栈 | 专用内核 Trap 栈顶 |
| Trap 入口交换后 | 专用内核 Trap 栈 | 原用户 sp，保存到帧第 2 槽 |
| C 回调期间 | 专用内核 Trap 栈上的 C 帧 | 0 |
| 继续用户执行前 | 仍在专用内核栈，最后恢复用户 sp | 重新放入专用内核 Trap 栈顶 |
| 结束后 | 原内核调用栈 | 调用前原值 |

独立 Trap frame 沿用真实布局，共 288 字节。进入回调前恢复原内核 gp/tp，避免用户改写它们后影响 C 代码。

## 4. 保存与恢复边界

保存原内核 ra、sp、gp、tp、s0～s11，以及 stvec、sscratch、sstatus、sepc、sie。扩展窗口屏蔽中断，单核、单实例、非嵌套，不支持并发用户任务、浮点或向量上下文。caller-saved 通用寄存器遵守普通函数调用约定，不保证等于调用前值。

进入 U 前为用户通用寄存器提供零初值并设置用户 sp，不将内核保存上下文的地址作为初值传给用户。回调要求继续执行时，底层拒绝 SPP=1 的返回状态，防止把 U 返回错误变成 S 执行；回调对 epc、页权限和其他帧修改仍需可信上层保证。

返回 S 调用者后，上层负责撤销测试页表、刷新 TLB 并恢复原 satp。基础 stvec、sscratch 和中断状态由底层恢复。切换扩展与正式时钟中断共存、异常兜底及最终原评分回归，要在共同联调时验证，不能由独立夹具结果代替。

## 6. 本人实际验证结果（2026-10-27）

QEMU 4.1.1 下五个编译单元、链接和镜像生成成功；正常往返、重复往返及拒绝重入、错误回调动作后的恢复三个场景均通过。每轮两次 U 态 ecall，实际 cause=8、SPP=0；用户 sp=0x401ff0，Trap frame 位于专用内核栈。本次帧地址为 0xffffffffc020dee0，属于该镜像的实测值，重新链接后可能变化。

进入回调的两处 epc 为 0x40001c、0x40003c。第二次 ecall 能执行，说明第一次回调修改 a0、epc 后用户确实继续执行。ABI 探针和返回后的 CSR 比较均通过。原始证据位于 logs/member-a-switch-*。

这些结果支持本候选底层实现；上层成员尚未确认接口，测试用户程序、页表与回调仍是夹具。还需进行正式上层接入、实际中断/异常路径互审和原评分回归。
