**真实管理器接口**

由 `kern/mm/buddy_pmm.h` 声明：

```c
extern const struct pmm_manager buddy_pmm_manager;
```

通过以下回调调用被测实现：

```c
buddy_pmm_manager.init();
buddy_pmm_manager.init_memmap(base, n);
buddy_pmm_manager.alloc_pages(n);
buddy_pmm_manager.free_pages(base, n);
buddy_pmm_manager.nr_free_pages();
buddy_pmm_manager.check();
```

各成员的真实签名以 `kern/mm/pmm.h` 为准。

**当前分配契约**

- 请求 n 页，实际占用最小的、能够容纳 n 的二次幂页数 k。
- 释放时传原始请求 n，而不是实际块大小 k。
- 计数按实际占用 k 变化。
- 同阶块的选择次序未约定，不得断言一定返回最低地址。
- 初始区间可不规整，可以分多次登记。
- 伙伴关系以绝对物理页号为基准。
- 空闲块首带 `PageProperty`，property 为块的实际页数。
- 已分配页面不带空闲块首标志。
- 不支持部分释放、错误长度、重复释放及非首地址释放。
- 非法输入触发 assert/panic；普通分配失败返回 NULL。
- `.check` 进行基础不变量检查。
- 当前只考虑串行操作。

**框架语义**

- `pages` 是 Page 描述符数组起点。
- `nbase` 是 DRAM 起始物理页号。
- `npage` 是物理页号上界。
- 描述符数量为 `npage - nbase`。
- `page2ppn(p)` 对应 `p - pages + nbase`。
- `page2pa()` 返回物理地址数值，宿主测试不能把它当宿主指针解引用。
- 页面大小由 `PGSIZE` 定义。
- 通过真实 Page 状态宏建立初始保留页状态。
- 相关类型与宏来自真实工程头文件，不得在测试中重新定义另一套。

**宿主适配约束**

- 宿主测试使用原生 GCC，不使用 RISC-V 交叉编译器生成宿主程序。
- 不执行 RISC-V 特权指令，不调用 SBI。
- 可以提供 `cprintf` 和断言所需的 `__panic` 平台实现。
- 适配代码只处理输出和进程终止，不实现分配逻辑。
- `panic` 是框架宏，应适配其调用的真实函数，
  不能通过替换 assert 或 panic 宏跳过检查。
- 工程自定义 `size_t` 等类型可能与宿主标准头冲突；
  应隔离平台适配编译单元或采取兼容的构建组织方式，
  不修改公共头文件来解决。
- 不复用内核 obj 目录中的 RISC-V 对象文件。
- 宿主产物放在独立子目录，与内核构建隔离。

## Case 1 初始化为空

**前置条件**
- 模拟环境有效，但未登记任何空闲页。

**操作与预期**
- 调用 init。
- 空闲页数为 0。
- 申请 1 页返回 NULL，计数保持 0。
- 若重复开展该用例，使用全新夹具状态。

## Case 2 单页与各阶精确申请

**前置条件**
- 登记一个物理页号对齐、长度为二次幂的区间。
- 用例规模不超过当前元数据容量。

**操作与预期**
- 覆盖从单页到该测试区间最大阶的申请。
- 返回非 NULL。
- 实际块大小与请求相同。
- 首物理页号按块大小对齐。
- 区间全部落在已登记范围。
- 计数准确减少，释放后恢复。
- 关键操作前后调用 check。

## Case 3 非二次幂申请

**操作与预期**
- 至少测试 3、5、9 页请求，分别实际占用 4、8、16 页。
- 分配对齐和计数按实际占用判断。
- 使用原始请求长度释放，计数恢复。
- 不得在正常用例中用向上取整后的长度替代原始长度释放。

## Case 4 连续分裂与耗尽

**前置条件**
- 登记一个小型、对齐的二次幂区间。

**操作与预期**
- 连续申请单页直到耗尽。
- 所有地址互异，所有返回区间合法。
- 成功次数等于初始页数。
- 耗尽后再申请返回 NULL，状态不变。
- 按非原始顺序释放，计数逐次正确。
- 全释放后可以重新申请整个大块。

## Case 5 正确伙伴递归合并

**前置条件**
- 使用可手算的对齐小区间。

**操作与预期**
- 分配形成多个小块。
- 释放真正伙伴后可以申请相应上阶块。
- 分阶段验证多级递归合并，不能只检查最终空闲总量。
- 不要求同阶选择固定地址；
  如需精确地址断言，先构造只有唯一合法候选的状态。

## Case 6 相邻但非伙伴

**手算场景**
- 在 nbase 为 8 的倍数的条件下，登记下标 `[0, 8)`。
- 连续申请 4 个 2 页块，按返回地址识别它们，
  不假定申请顺序就是地址顺序。
- 保持外侧 `[0,2)` 与 `[6,8)` 存活，
  释放中间 `[2,4)` 与 `[4,6)`。

**预期**
- 空闲总量为 4 页。
- 中间两块相邻，但不是同阶伙伴。
- 申请 4 页必须失败，状态和计数不变。
- 最后释放外侧分配，恢复整个 8 页块。

## Case 7 不规整初始区间

**手算场景**
- 使用足够大的描述符数组。
- 在真实 nbase 满足相应对齐的条件下，登记 `[3,16)` 共 13 页。

**预期**
- 初始空闲数精确为 13。
- 连续单页分配可恰好取得 13 个不同页面。
- 不取得下标小于 3 或大于等于 16 的页。
- 全部释放后恢复 13 页。
- 未登记区域保持保留状态。
- 另补充一个尾部不规整的区间，避免只测到长度不规整、
  但末端恰好对齐的一种情况。

## Case 8 多次登记与空洞

**场景 A**
- 先登记 `[20,24)`，再登记 `[16,20)`。
- 当 nbase 满足 8 页对齐时，能够分配 `[16,24)` 的 8 页块。

**场景 B**
- 登记 `[32,34)` 与 `[36,38)`。
- 总空闲数为 4，但申请 4 页失败。
- 不得跨空洞合并；失败后计数和可用空间不变。

**要求**
- 场景之间重置夹具。
- 保留并检查空洞页状态。
- 如果真实 nbase 不满足上述对齐，调整手算下标，
  并在文档写明实际物理页号，不能忽略绝对页号约束。

## Case 9 分配失败保持状态

**覆盖**
- 请求超过总空闲量。
- 总量够但没有足够大的连续伙伴块。
- 极大请求，例如 size_t 的最大值。

**预期**
- 返回 NULL。
- 原有存活分配仍有效。
- 空闲页数不变。
- check 通过。
- 失败后继续正常分配与释放，结果符合原有资源状态。

## Case 10 存活区间与交错多轮操作

**操作与预期**
- 混合不同请求大小。
- 每次保存原始请求和独立计算的实际占用。
- 用独立存活区间表检查所有实际占用区间两两不重叠。
- 按确定的交错顺序分配、释放和重新申请。
- 每次核对空闲页数。
- 多轮结束后空闲量恢复，仍可申请初始最大块。
- 如使用伪随机序列，固定并输出种子。

**内存内容验证**
- 若测试对象写入完整性，另建有界宿主字节数组作为模拟页内容。
- 依据已验证的描述符下标映射到该数组。
- 为不同存活分配写入不同模式，检查其他操作未破坏内容。
- 不直接解引用模拟物理地址。
- 该验证只能说明模拟模型中的区间隔离，
  不能宣称真实 MMU 或 QEMU 数据访问已验证。

## Case 11 非法申请与释放

以下每一项使用独立异常场景：

- 申请 0 页。
- 释放时 n 为 0。
- 释放 NULL。
- 释放描述符范围外的地址。
- 释放指向描述符内部的未对齐地址。
- 释放分配块的非首描述符。
- 使用与原始申请不符的长度释放。
- 申请 3 页后错误地用 4 页释放。
- 同一分配释放两次。
- 释放保留页或未登记页。

**预期**
- 到达对应操作时触发框架断言。
- 正常返回判失败。
- 无关位置的断言、段错误、超时不能判通过。
- 保留场景名称和诊断输出以便定位。

## Case 12 非法登记与容量

独立异常场景覆盖：
- 登记 0 页。
- 起点或区间越界。
- 重复登记。
- 部分重叠登记。
- 输入区间中存在非保留页。
- 模拟描述符数量超过静态容量。

**预期**
- 触发框架断言。
- 不得通过给已登记页面重新设置 Reserved 来绕过重叠检查。
- 越界和容量测试避免测试夹具自身先发生越界。
- 不依靠异常进程退出后的状态推断失败前完全无修改；
  这一点还需要对实现验证顺序进行代码审查。
